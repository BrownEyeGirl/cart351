Data Collection as a Intermediary Process

Notes, by: Skyla Trousdale

Journal P6

Reading: The Point of Collection by Mimi Onuoha

Terms

Corollary: a proposition that is extends and is often appended to one thats already provided
Subjects in data: those who collect
Objects in data: those who make up the collected data

5 thesis around data collection

1. Data sets are the results of their means of collection.

The data collected depends on how the collectors need to use it. Eg. In 2012, the Department of Justice reported over 50x hatecrimes as the FBI Crime Reporting Program because the CRP collects voluntarily reported data from law enforcement agencies.

2. As we collect more data, we prioritize things that fit patterns of collection.

“The effect of abstracting the world is that the world starts to structure itself in the image of the capta and the Code.” Rob Kitchin and Martin Dodge, written in Code/Space

Data collection is software-mediated, rigid algorithmic structures determine output, sometimes flattening the nuance of experience with simple input/output systems that were designed before the data was collected. Eg. Biometric data collection: people have to be conceptualized as machine-readable

The Point of Collection by Mimi Onuoha.pdf

3. Data sets outlive the rationale for their collection.

Eg. spotify can rationalize collecting mic, location, usage info to improve the listening experience, but after the data is collected the usage can be extrapolatedpast the agreed upon use.

4. Corollary: Especially combined, data sets reveal far more than intended.

Data collection is an intermediary process; first used for basic application support, it can imply data about the user (the object of the data) they never consented to sharing.

“data we’re willing to share can imply conclusions that we don’t want to share.” - Bruce Schneier

5. Data collection is a transaction that is the result of an invisible relationship.

Remembering that there are those collecting and those collected helps us see “data as an intermediate result, one piece in a larger process, something that is as much human-oriented as it is systematic” - p4

There are two sides of data collection: systematic -- machine side, oversimplification, and human tensions and biases -- human side, implied social biases assumed from the data.

Connection to projects

Data collection as an intermediary aspect to imposing larger systems, often different than the original intent of the data, can be harmful to the user without the user realizing it. I find this inspiring because these things happen on the machine side, then only become human readable after the data is algorithmically synthesized. For a project I think it would be interesting to synthesize the data algorithmically in a way that a user can see it; especially in the time of AI, when the weights of large verticies models are hidden from the user. I would find it fascinating to design something that makes heavily biased or ridiculous assumptions on the user based on data provided, making connections that are offensive, caricaturist conclusions to the data provided.
Eg: digital vending machine - a website where you input info on your credit card (fake!) & it changes the price/output of goods, then tries to lobby for some dumb political policy. For example, if you're from Quebec, it takes your name, postal code, then ups the price based on postal code income, then starts running targeted ads like "Paint fumes are bad for you" and "aren't there too many painted murals in Le Plateau?" forcing the user to make human conclusions based on unconnected data and political assertions.
